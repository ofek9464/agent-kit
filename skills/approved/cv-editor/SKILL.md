# CV editor

Produce a CV that lets a recruiter understand the candidate's relevant experience, contribution, and fit. Match the requested role, language, seniority, and editing scope. Preserve the user's chosen platform and template; a content edit does not authorize a redesign or a job application.

## Establish the evidence

Read the supplied CV and relevant supporting material. Reuse settled preferences. Ask only for gaps that affect the result, grouping questions in the available popup; if it cannot collect answers or the user reports it is invisible, explain briefly and ask in chat. For project examples, give a concrete topic rather than a broad request to describe the candidate.

Distinguish the candidate's personal work from a team's system capabilities. Record what they built, operated, or improved, the tools used, the deployment context, and supported outcomes. Do not invent metrics, ownership, seniority, production use, or qualifications. Supporting architecture documents can clarify components but do not establish who implemented each one. Resolve conflicts before turning them into claims; keep unresolved details out of the final CV.

Separate earned certifications, completed courses, and ongoing study. Preserve exact verified credential names and relevant expiration status. Do not present an unfinished exam as a certification held. Use an accurate training entry when appropriate, without implying completion. Ask before including uncertain client or project names; descriptive anonymous labels can communicate the work without exposing internal names. Exclude private infrastructure identifiers, access details, and third-party contact information from the CV.

For substantial revisions or multiple versions, maintain a reusable evidence record in the candidate's project directory, separate from the application CV. Read the evidence-record and scale-discovery sections of [the CV working guide](references/cv-working-guide.md) when building that record or clarifying project scope. Reuse existing records; a small wording edit does not require creating one. Ask about meaningful scale or before/after evidence when it would improve a claim, without requiring a number in every bullet.

## Edit for the target role

Use `clear-human-editor` for wording and reader focus, then apply `unslop` once, reusing them if already read. Keep technical names precise and the prose direct. Avoid inflated claims, generic enthusiasm, and lists of tools without an account of the work.

Plan the CV's emphasis from the target role and verified evidence. Lead with the strongest relevant work, preserve useful career progression, and reduce repeated duties. Show both breadth of responsibility and selected concrete projects; do not make one project stand for the whole role. Scale detail and length to the candidate rather than enforcing one page regardless of readability.

For each useful example, connect the candidate's action to the system's purpose and a supported result. Delivery to production, replacing manual steps, or enabling a workflow can be meaningful without a numerical improvement. Distinguish operating a platform from writing its application code. Include skills at their evidenced level; do not turn familiarity from training into professional experience.

When a job description is supplied, adapt emphasis and terminology to real matches. Do not fabricate missing requirements or force every keyword into the CV. Browse only when external role or credential information needs verification; do not require market research for an ordinary rewrite.

For a supplied job description, read the requirement-mapping section of [the CV working guide](references/cv-working-guide.md). Map required and preferred qualifications to verified experience and unresolved gaps before selecting content. Do not present a keyword heuristic as an actual ATS score or hiring probability.

## Deliver and verify

Use the matching artifact tools for the requested output: Documents for editable Word files, PDF for PDF inspection or export, or the connected Canva workflow for Canva designs. Preserve a reusable base and make a separate version when tailoring would overwrite a base the user wants to keep. Do not replace a fixed-page resume template with a flowing document merely because both are editable.

Check the revised content against the evidence and the latest corrections. Render and inspect the relevant pages for readable type, clipped text, overlapping sections, and pagination. Keep authorized work moving through routine layout repairs. Follow any actual tool requirement to preview and obtain approval before saving; do not add a separate skill-level approval gate.

For a finished CV, use the delivery checks in [the CV working guide](references/cv-working-guide.md): confirm the role and strongest evidence are clear at a glance, verify contact links, and inspect extracted PDF text when delivering a PDF. Text extraction is a parsing check, not proof of compatibility with every recruiting system. Report unavailable checks accurately.

Verify persistence after saving by reading the saved artifact, including the candidate's name and newly changed passages. A temporary editing transaction, generated preview, or copied template is not a saved CV. Return the link to the verified candidate-specific result and state any outstanding factual gaps. Keep CV drafts and scratch files in the user's CV project directory rather than the skills repository.
